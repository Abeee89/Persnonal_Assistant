You are a **Senior Full-Stack Web Developer, Software Architect, Database Engineer, Product Designer, and UI/UX Designer** with extensive experience building productivity and personal management applications.

I want to build a web application called **Personal Activity**.

Your task is to create a comprehensive **Software Design Document (SDD)** that can be used as the technical blueprint for developing this application.

Do **not** write the application source code yet.

The goal is to produce a practical, technically sound, scalable, maintainable, privacy-focused SDD that can later be used by developers or AI coding agents to implement the application step by step.

---

# 1. Product Overview

**Personal Activity** is a personal productivity and life-logging web application.

The application should allow a user to:

* Track daily activities
* Write daily journals
* Manage tasks and todos
* Create and track personal goals
* Track habits
* Record progress
* Store photos and attachments
* Review previous activities
* View activities through a calendar and timeline
* Analyze personal productivity
* Perform daily, weekly, and monthly reflections
* Search historical personal data
* Export and restore personal data

The application should function as a **private personal activity management system**, not as a social network.

The main principles are:

1. Privacy
2. Data ownership
3. Local-first architecture
4. Simplicity
5. Good UX
6. Performance
7. Maintainability
8. Extensibility
9. Easy backup and restore

---

# 58. Important Instructions

Before producing the final SDD:

1. Analyze the product requirements.
2. Identify ambiguities.
3. State reasonable assumptions.
4. Evaluate technology choices.
5. Compare architectural alternatives.
6. Select the recommended architecture.
7. Identify technical risks.
8. Define the MVP boundary.
9. Produce the final SDD.

Do not write application source code.

Do not create unnecessary complexity.

Do not assume cloud infrastructure is required.

The application must remain functional without AI or external services.

Use **Mermaid diagrams** for:

* System architecture
* ERD
* User flows
* Data flows

Use tables where comparisons are useful.

The final document should be technically detailed enough that another developer or AI coding agent can use it as the implementation blueprint without having to redesign the architecture from scratch.

The ultimate product vision is:

> **A private, local-first Personal Activity OS that combines activity tracking, journaling, tasks, goals, habits, calendar, statistics, personal reflection, and optional AI-powered insights into one clean and intuitive application.**
